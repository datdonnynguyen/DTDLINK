Three defensible choices, and they are not equivalent: fill with 0 says "never seen means safe"; fill with the mean says "never seen means average risk"; add a flag says "never seen is itself information". The third is usually strongest and costs one line.

Order matters, and so does where the fill value came from. Build the seen flag before you fill, or there is nothing left to detect. And the fill value must come from the training data. Using the overall mean leaks the test set into your features.
The leak that gives you free marks you did not earn. That lookup table aggregates the label. Build it on the training split only and the model scores F1 0.900 on the full SMS data. Build it from every row, test included, and the same code scores F1 0.954. Those 5.3 points are not real: the test messages contributed their own labels to the table the model then looked them up in. Any feature built by aggregating the label has to be fitted on train and applied to test, never both at once.

10The index, and reset_index

The index is the row labels down the left-hand side. It is not a column, and it causes more confusion than any other part of pandas.

# after any filter, the index keeps the ORIGINAL labels
f = d[d.label == "ham"]
f.index.tolist()                         → [1, 3, 4]   gaps!
f.reset_index(drop=True).index.tolist()  → [0, 1, 2]   renumbered
# groupby returns a Series indexed by the group, not a DataFrame
g = d.groupby("label")["length"].mean()
g.index.tolist()                         → ['ham', 'spam']
g.reset_index().columns.tolist()         → ['label', 'length']   a normal table
commandwhat it does
.reset_index()Moves the index into a column and renumbers from 0. Use after groupby, so the group key becomes an ordinary column you can merge on.
.reset_index(drop=True)Throws the old index away and renumbers. Use after filtering or sampling, when the old row numbers mean nothing.
.set_index("col")The reverse: turn a column into the index.
.reindex(other.index)Align to another object's index, filling gaps with NaN.
When it bites. After filtering, f.iloc[0] still works but f.loc[0] raises an error, because no row is labelled 0 any more. And pd.concat on two filtered frames produces duplicate index labels, which quietly breaks later lookups. Both are fixed by reset_index(drop=True), which is why you should reach for it after almost every filter.
Which one do I want? Ask whether the current index holds information. After groupby it does, the group name, so use plain reset_index(). After a filter it does not, only old row numbers, so use reset_index(drop=True).

spam = d[d["label"] == 1]        # one class only, so the label is constant

Compare each cluster's mean against the overall mean, divided by the standard deviation so features on different scales are comparable, take the two or three that differ most in either direction, and read a couple of real examples aloud.

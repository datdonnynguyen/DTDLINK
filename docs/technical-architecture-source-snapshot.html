01

Luồng kỹ thuật tổng thể: ZIP → raw → cleaned → features

Mũi tên data flow đi theo chiều dữ liệu được chuyển; import / call đi từ bên gọi tới module được gọi. Đây là các bước được chạy riêng, phối hợp thông qua file trên máy; chưa có một service điều phối tự động toàn bộ pipeline.

Điểm kết thúc hiện tại: data/processed/url_features.csv chứa 6 cột metadata + 36 numeric features. data_cleaning.py không gọi data_audit.py; feature_extraction.py không gọi cleaning. Mỗi bước đọc artifact mà bước trước tạo.
02

File nào import và gọi file nào?

Trong bốn module xử lý chính, import nội bộ duy nhất là feature_extraction.py → url_parser.py. Notebook và tests import trực tiếp module chúng sử dụng. Các node trùng tên ở những sơ đồ khác nhau vẫn chỉ cùng một file.

Entry points thực tế

Chạy từ thư mục gốc dự án:

PYTHONPATH=src .venv/bin/python src/dtdlink_ml/data_audit.py
PYTHONPATH=src .venv/bin/python src/dtdlink_ml/data_cleaning.py
PYTHONPATH=src .venv/bin/python src/dtdlink_ml/feature_extraction.py

Hai notebook cũng gọi cùng code của audit/cleaning. Extractor hiện có CLI và hàm Python dùng lại, chưa có notebook riêng trong dự án.

Dependency quan trọng

  • pandas: audit và cleaning thao tác bảng dữ liệu.
  • tldextract: parser tách domain bằng snapshot đi kèm thư viện; tắt cập nhật mạng và cache.
  • csv / json / hashlib: đọc, ghi artifact và tính fingerprint.
  • scikit-learn / joblib: đã có trong requirements; model trong test_environment.py chỉ là ví dụ kiểm tra môi trường.
03

Luồng cleaning theo đúng thứ tự trong code

Nguồn chính: data_cleaning.py:161–277. Hàm run_cleaning_pipeline() tự điều phối các bước dưới đây; load_and_prepare_dataset() là helper khác, không được hàm này gọi.

Code tạo target sau trim và trước cách ly conflict. Dòng conflict giữ thêm source_record_number để truy nguồn. Unicode, control characters và URL dài được giữ lại. Các số lượng trong sơ đồ lấy từ reports/cleaning/cleaning_audit.json đã lưu, không phải một lần chạy lại toàn bộ dữ liệu ở lần lập tài liệu này.
04

Hai cách dùng chung parser và feature logic

Đường trái xử lý một URL trong bộ nhớ. Đường phải xử lý từng dòng CSV và ghép metadata. Cả hai đều đi qua parse_url() và _extract_features_from_parsed(); nhãn chỉ được sao chép, không được dùng để tính features.

Hợp đồng của url_features.csv

6 cột metadata

url, type, target, registrable_domain, tld, parse_issues

36 features theo thứ tự FEATURE_NAMES

Độ dài; số ký tự / token; scheme / HTTPS; IP / port; brand; Unicode / encoding; trạng thái parser.

Schema được khóa bằng kiểm tra thứ tự. Tần suất TLD học từ dataset chưa được tính; source ghi rõ phải đợi train split.

Ví dụ đã gọi trực tiếp qua code

https://paypal.com@example.net/login?next=%2Fhome

url_parser.py: host = example.net, user-info = paypal.com.

feature_extraction.py: has_at_symbol=1, brand_in_userinfo=1, has_encoded_separator=1, parse_ok=1; tổng cộng 36 features.

Đầu ra là tín hiệu số, chưa phải dự đoán nguy hiểm. parse_ok phản ánh khả năng phân tích cú pháp.

05

Frontend, điều hướng, API, database và dịch vụ ngoài

Không có đủ code để dựng luồng full-stack hoặc luồng chuyển màn hình. Các thành phần chưa tồn tại không được biểu diễn thành service đang chạy.

CHƯA CÓ SOURCE

Frontend / screens

Không có component React, route config hay mã điều hướng sản phẩm. Vì vậy không có cạnh render hoặc navigate giữa màn hình để xác minh.

CHƯA CÓ SOURCE

Backend / HTTP API

Không có FastAPI app, API endpoint, request/response contract hay HTTP client của sản phẩm. Hàm Python tái sử dụng chưa phải HTTP API.

KHÔNG CÓ DATABASE

Lưu trữ cục bộ

Code đọc/ghi CSV, JSON và JSONL qua filesystem. Không có SQL, ORM, connection string hoặc lớp truy cập database.

OFFLINE

Dịch vụ bên ngoài

Dataset lấy từ ZIP cục bộ. Parser dùng suffix_list_urls=(), fallback_to_snapshot=True, cache_dir=None; không có API lookup website trong pipeline này.

CHƯA CÓ MODEL SẢN PHẨM

Training / inference

Chưa có split, training, clustering, evaluation hoặc predict.py. models/ chỉ có .gitkeep; không có trained model để phục vụ request.

06

Vai trò file và bằng chứng để kiểm tra sơ đồ

Tên hàm, số dòng và trích đoạn dưới đây được đối chiếu với source tại thời điểm lập tài liệu. Đường dẫn tính từ thư mục gốc dự án. Bấm “Mở source” khi giữ tài liệu trong docs/.

Phương pháp: đọc nội dung 5 file Python trong package (gồm __init__.py), code cells của 2 notebook và 4 file tests; đối chiếu artifact JSON đã lưu. Bỏ qua môi trường .venv, cache, file tự sinh và thư viện không cần thiết. Không chạy lại pipeline toàn bộ dataset, không thay đổi source xử lý và không thực hiện network lookup.

Tài liệu độc lập, không CDN, không font ngoài, không gửi dữ liệu. Sơ đồ SVG được tạo tại máy khi mở file; có thể in hoặc lưu PDF bằng nút đầu trang.
